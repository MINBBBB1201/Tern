# Tern 작업 규약 (Working Agreement)

> **이 문서는 매 라운드 반복되는 고정 규칙이다.** 저장소의 `CLAUDE.md`에 포함시켜 세션마다 자동 로드되게 할 것.
> 라운드별 브리프는 이 규약을 전제로 하며, 여기 적힌 내용을 다시 적지 않는다.
> 브리프와 이 규약이 충돌하면 브리프가 우선하되, **충돌 사실을 보고에 명시한다.**

---

## 1. 역할과 품질 기준선

세계 최고 수준의 웹 디자인 엔지니어이자 프로덕트 엔지니어로서, 요구된 것을 그대로 구현하는 데 그치지 않고 **요구 뒤의 의도**를 달성한다.

기준은 Linear / Stripe / Apple 수준의 절제된 전문성. 단 **"절제"가 "안 보임"이 되면 실패다.** 의도한 효과가 결과물에서 인지되지 않으면 구현하지 않은 것과 같다.

디자인 시스템: **Civil Twilight** (잉크/더스크 팔레트, 글래스 머티리얼, Space Grotesk). 새 시각 언어를 도입하지 않는다.

브랜드 보이스: 확신 있되 정직. 과장, 가짜 긴급성, 검증 불가한 주장 금지.

---

## 2. 절대 원칙

위반이 불가피한 항목은 **구현하지 말고 스킵한 뒤 구체적 사유를 보고한다.** "안 함"만 적는 것은 보고가 아니다.

1. **실데이터만.** 추정치·더미·플레이스홀더 통계로 UI를 채우지 않는다. 데이터 소스가 없으면 그 항목을 반려한다.
2. **검증된 주장만.** Terms/Privacy에 없는 법적·정책적 주장을 새로 만들지 않는다. 카피는 기존 문서와 일치해야 한다.
3. **조용한 추측 금지.** 확신이 없으면 추측한 채로 진행하지 말고 플래그한다. (§6)
4. **무손상.** §3의 불가침 목록을 건드리지 않는다.

---

## 3. 불가침 (Do Not Touch)

동작이 바뀌면 안 되는 영역. 이 영역을 수정해야만 목표 달성이 가능하다면 **구현하지 말고 먼저 보고하고 멈춘다.**

- Duffel 검색 연동 및 오퍼 파싱
- 어필리에이트 링크 (Duffel Links, Travelpayouts) — URL 파라미터 포함
- 인증 플로우 (Firebase, `auth.flytern.site`, authDomain 설정)
- next-intl 로케일 시스템 (en / ko / ja / zh)
- 기존 애니메이션: globe 태양 위치 로직, ambient bird, bird→ticket 모프
- `tsc` / `eslint` 클린 상태

---

## 4. 라운드 규약

- **한 라운드 = 하나의 리뷰 단위.** 브리프에 없는 다음 그룹을 임의로 시작하지 않는다.
- **커밋 게이트 — 내 승인 전에는 커밋하지 않는다.** 브리프에 이 문장이 없어도 항상 적용된다. (I3 사고 이후 확정)
- 승인 후 항목별 커밋 → 푸시.
- 라운드의 결정·반려·발견을 `docs/backlog.md`에 기록한다.

---

## 5. 검증 규약

**"코드상 맞음"은 검증이 아니다.** 증빙은 변경의 성격에 맞는 것을 선택한다.

| 변경 유형 | 통과 증빙 |
|---|---|
| 시각적 변경 | 전/후 캡처 2장. **나란히 놓았을 때 육안으로 차이가 확실해야 통과.** 수치는 맞지만 캡처로 구분 안 되면 실패 → 재조정 |
| 서버 응답·메타데이터 | 실제 요청의 **응답 본문 발췌** (`curl` 등). devtools 스크린샷은 JS 실행 후라 증빙이 안 될 수 있음 |
| 로직·데이터 | 실제 입력 → 실제 출력 기록, 또는 통과한 테스트 |
| 삭제·정리 | 빌드 성공 + `tsc`/`eslint` 클린 로그 |

캡처는 반드시 **파일로 저장**하고 정확한 경로를 보고한다. 인라인 표시만으로는 검증 불가.

파일명: `docs/screenshots/{라운드ID}-{로케일}-{화면}-{before|after}.png`

**캡처 함정 (실제로 당한 것):**

- 결과 화면은 데이터가 실제로 있는 상태에서 찍는다. 기본값 때문에 빈 상태가 찍히면 검증이 아니다 — 조건을 URL로 고정할 것.
- 서버 렌더와 클라이언트 렌더 결과가 다를 수 있다. hydration 이후 상태인지 확인할 것.

---

## 6. 불확실성 프로토콜

모든 결과에 확신도를 자가 표기한다.

- **확실** — 코드 또는 실행 결과로 직접 확인함
- **합리적 추정** — 근거는 있으나 직접 확인은 못 함. 근거를 함께 적을 것
- **검증 필요** — 내가 판단할 수 없는 영역. **누가 무엇을 확인해야 하는지**까지 명시

"검증 필요"에 반드시 들어가야 하는 것: 내가 원어민이 아닌 언어의 자연스러움(ja/zh), 외부 API의 문서화되지 않은 동작, 실제 트래픽에서만 드러나는 성능 가정.

**10분 이상 코드를 추적해도 확정하지 못한 사실은 추측으로 메우지 않는다.** 무엇을 못 찾았는지 보고하고 멈춘다.

---

## 7. 탐색 예산

- 코드 조사는 목적 지향으로. 브리프 범위 밖 리팩터링을 하지 않는다.
- 범위 밖에서 버그·개선점을 발견하면 **고치지 말고** `docs/backlog.md`에 기록하고 보고에 한 줄 남긴다.
- 같은 문제를 두 가지 방식으로 시도해서 둘 다 실패하면, 세 번째를 시도하기 전에 보고한다.

---

## 8. 완료 보고 스키마 (고정)

리뷰 비용을 줄이는 것이 목적이다. 서술형 문단보다 **항목별 사실 나열**을 우선한다.

1. **선행 확인 결과** — 게이트 통과 여부. 실패했으면 여기서 끝내고 판단을 요청
2. **항목별 결과** — 각 항목: 한 일 / 통과 기준을 충족했다는 증빙 / 캡처·로그 경로
3. **스킵·반려** — 항목과 구체적 사유 (전제 조건 중 무엇이 왜 불충족인지)
4. **확신도 플래그** — "검증 필요"로 분류된 것, 누가 무엇을 확인해야 하는지
5. **건드리지 않은 발견** — backlog에 기록한 범위 밖 이슈
6. **남은 리스크**
7. **커밋 대기** — 승인 요청. 승인 전 커밋하지 않았음을 확인

## 9. 누적 교훈 (반복 금지 — 매 라운드 갱신)

과거에 실제로 틀렸던 것들. 새 실수가 나오면 이 목록에 추가한다.

- **G3** — `rotateX` 1.5도. 코드상 값은 있었으나 캡처로 구분 불가. 미세 모션은 구현 직후 캡처 대비로 먼저 확인할 것.
- **I3** — 승인 없이 커밋됨. 커밋 게이트는 브리프 명시 여부와 무관하게 항상 적용.
- **I4** — `Intl.formatRange`가 Node와 Chrome의 ICU 구분자 차이로 hydration mismatch 유발. 로케일 포매터는 서버·클라이언트 양쪽 출력을 확인할 것.
- **I4** — `/booking` 기본 날짜가 오늘이라 Duffel 당일 오퍼가 없어 빈 상태가 캡처됨. 결과 화면 캡처는 조건을 URL로 고정.
- **I4** — 대량 생성한 프로즈에 영어 단어 잔재와 키릴 문자 조각이 섞임. 대량 텍스트는 스크립트로 문자셋·언어 검사를 돌릴 것.
- **I6** — Turbopack 스테일 컴파일로 `/booking`이 **404**를 냈다. 코드는 멀쩡했고 stash/pop으로 재컴파일하니 200. 검증 스크립트가 전부 `null`을 뱉으면 변경을 의심하기 전에 **라우트가 200인지 `curl`로 먼저 확인**할 것. 빈 결과와 죽은 라우트는 구분해야 한다.
- **I6** — 진단 캡처와 검증 캡처가 같은 파일명을 써서 이전 라운드 증빙이 덮어써졌다(untracked라 복구 불가). 캡처 경로는 `{라운드ID}-{before|after}-...` 규약을 지키고, `-diag-` 산출물에 재기록하지 말 것.
- **I6-b** — 성능 임계값을 refreshrate **비율**로만 잡으면 120Hz 패널에서 84fps를 요구해 정상 기기를 강등한다. 프레임 예산은 비율 + **절대 fps 상한**을 함께 걸 것.
- **I6-b** — 품질 사다리를 단방향으로 만들었는데 `PerformanceMonitor` 상한을 도달 가능하게 두어, 60fps 기기가 incline↔decline 플립플롭으로 최하 티어까지 떨어졌다. 올라갈 계획이 없으면 **상한을 도달 불가로 둘 것.**
- **I6-b** — 3D 씬을 새 뷰포트에 켤 때는 **켜지는지**가 아니라 **구도가 성립하는지**를 캡처로 볼 것. globe 반지름이 `planeH` 기준이라 세로 화면에서 지름이 화면 폭을 넘어 히어로 카피를 덮었다. "기능은 됨"과 "쓸 수 있음"은 다르다.
- **I6-b** — 페이지에 자체 rAF 샘플러를 얹어 FPS를 재면, CPU 스로틀 상태에서 그 샘플러 자신이 굶어 실제보다 낮은 값이 나온다. 앱 내부 계측(`PerformanceMonitor` 콜백)과 교차 확인할 것.
- **I6(1차 브리프)** — 브리프를 쓴 쪽이 대화 압축으로 이미 완료된 라운드를 기억에서 잃어버려 중복 지시를 보냄. 게이트(§8-1)가 커밋 로그 대조로 잡아내고 재구현 없이 멈춰서 중복 작업을 막음. 앞으로 새 브리프를 받으면 브리프의 전제(직전 라운드 번호·완료 여부)가 실제 저장소 상태와 맞는지 항상 먼저 대조한다.
- **I8** — 같은 URL을 두 라우트가 물면 승자가 **컴파일 순서에 따라 비결정적**이다. 직전 라운드가 `/guide/airport/ICN` 200을 관측하고 "무해한 죽은 코드"로 판정했으나, 깨끗한 서버에서는 4개 로케일 전부 404였다. **라우트 충돌에서 한 번의 200은 안전의 증거가 아니다** — 중복 라우트를 발견하면 관측 결과와 무관하게 제거 대상으로 다루고, 판정은 서버를 새로 띄워 재현할 것.
- **I9** — "프레임워크 제약이라 못 고친다"는 결론은 **그 버전의 문서를 읽고 내린 것이어야 한다.** I7이 404를 §3 저촉으로 보류했으나, `node_modules/next/dist/docs/`를 열어 보니 원인(`not-found.js`는 세그먼트 안 `notFound()`에만 반응)도 해법도 문서에 그대로 있었고 §3을 건드릴 필요가 없었다. AGENTS.md가 요구하는 문서 확인은 **코드를 쓸 때만이 아니라 "불가능하다"고 판정할 때 더 중요하다.**
- **I9** — `localeDetection`이 켜진 상태에서 접두어 없는 경로를 캡처하면 브라우저 Accept-Language를 따라간다. 실제로 en 캡처에 한국어가 찍혔다. 로케일별 캡처는 Accept-Language를 **명시 고정**하고 컨텍스트를 분리할 것(§5의 "조건을 URL로 고정" 의 헤더 판.)
- **I10** — 직전 라운드가 남긴 "한 줄이면 된다"를 그대로 믿지 말 것. 실제로는 고칠 지점이 3곳이었고(본문·메타데이터·**OG 이미지 라우트**) 결함도 2개였다. 특히 `generateStaticParams`가 일부만 순회해도 **라우트 자체는 동적으로 열려 있어** 목록 밖 입력이 그대로 렌더된다 — prerender 목록과 라우트 접근성은 별개다.
- **I11** — **dev 서버는 모든 페이지에 `<meta name="robots" content="noindex">`를 주입한다.** 이걸 모르고 tier 1 큐레이션 페이지가 noindex로 나오는 것을 보고 "기존 자산이 이미 죽어 있다"고 오판할 뻔했다. 실제 배포본에는 없었다. **robots·색인 관련 검증은 반드시 프로덕션 빌드(`next start`) 또는 실제 배포본에서** 할 것.
- **I11** — next-intl은 **메시지 번들 전체를 HTML에 실어 보낸다.** 카피 문자열을 grep해서 "이 문구가 렌더됐는지" 세면 렌더되지 않은 페이지에서도 1이 나온다. 조건부 렌더 검증은 문자열이 아니라 **실제 엘리먼트(클래스·태그)**로 셀 것.
- **I12** — **레이아웃 컨테이너가 곧 3D 스테이지인 경우, "보이는 영역"과 "요소의 박스"가 같다고 가정하지 말 것.** drei `<View>` 는 자기 DOM 박스의 aspect 로 카메라를 세운다. 히어로는 `minHeight:100vh` 지만 실제 높이는 콘텐츠라, 폰에서 1382px(aspect 0.28)가 되어 씬 전체가 **사용자가 볼 수 없는 프레임**을 기준으로 구성됐다. 데스크톱은 히어로가 정확히 1 뷰포트라 이 버그가 원리적으로 발생하지 않는다 — **"PC 에서 멀쩡함"은 모바일 레이아웃 버그의 반증이 아니라 오히려 전형적 증상**이다.
- **I12** — 투명 캔버스(`alpha:true`) 위에서 `PointsMaterial` + `vertexColors` 로 페이드를 주면 안 된다. 프래그먼트 알파는 `opacity * mapAlpha` 이고 **vertex color 를 보지 않으므로**, 페이드가 0 인 점이 rgb≈0·alpha=1 로 남아 **불투명 검정 사각형**을 찍는다. 페이드는 rgb 와 alpha 를 함께 구동하는 어트리뷰트로 옮길 것.
- **I12** — 파티클을 **프레임당 1개** 방출하면서 대상의 속도는 wall-clock 이면, 그 이펙트의 밀도는 기기 fps 에 묶인다. 저사양 폰에서만 "끊어져 보이는" 이펙트는 이 패턴을 의심할 것. 방출 기준을 **이동 거리**로 바꾸면 fps 와 무관해진다.
- **I12** — 같은 룰에 `height:` 를 두 번 써서 만드는 고전적 CSS 폴백은 **빌드의 CSS 옵티마이저가 마지막 것만 남기고 접어버린다.** 폴백이 필요하면 `@supports` 로 분리하고, **서빙된 청크를 직접 열어 확인**할 것.
- **I12** — Turbopack 스테일 CSS 를 이 라운드에서만 **3번** 밟았다(특히 `git stash`/`pop` 직후). 규칙: CSS 를 고친 뒤 검증하기 전에는 **서빙된 청크에서 바뀐 선언을 grep 해 확인**하고, 안 보이면 `.next` 삭제 후 재기동한다. 스크린샷을 먼저 찍고 "왜 안 바뀌지"를 고민하지 말 것.
- **I10** — 같은 규칙이 이미 다른 화면에 구현돼 있는지 먼저 찾을 것. 가이드 라우트의 §2-1 위반은 I5-4가 `/booking`에 `resolveBrief`로 이미 해결해 둔 것과 동일한 문제였고, 주석에 판단 근거까지 적혀 있었다. 새로 설계하기 전에 **기존 판례를 grep**하면 결정이 공짜다.
